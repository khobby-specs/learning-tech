System Architecture

// THE 5 LAYERS OF SYSTEM ARCHITECTURE DEPTH
1
Component Thinking
PHASE 1 — 2026 · Month 5
What do databases, servers, APIs, clients, networks do individually — and how do they connect? Draw the diagram before writing code. Ask: where does data live? How does it move? This habit, built now, changes how you approach every system for the rest of your career.
2
Tradeoff Reasoning
PHASE 2 — 2027 · Q3
Every design decision has costs. SQL vs NoSQL. Monolith vs microservices. REST vs GraphQL. You stop asking “what should I use” and start asking “what are the tradeoffs and which matter here.” Resource: System Design Primer.
3
Scale and Failure Thinking
PHASE 2–3 — 2028 · Q3
Design for failure as a normal condition. Replication, partitioning, consistency models. What happens when a database node goes down? The answers are architectural decisions. Resource: Designing Data-Intensive Applications — Kleppmann. Also: Netflix Tech Blog, Cloudflare Engineering, Uber Engineering.
4
Security-Integrated Architecture
PHASE 3 — 2029 · Q3
Security is structural — built into the design — not bolted on afterward. Zero-trust architecture. Threat modeling before building. AI system architecture with adversarial robustness as a design constraint from day one. Your security vertical + SA depth converging. Resources: CISA Zero Trust, OWASP ASVS, MITRE ATT&CK.
5
Novel System Design
PHASE 4–5 — 2030+ · Elite
Designing systems that do not exist yet for problems not fully defined. You are not implementing a known architecture — you are inventing one appropriate for a novel set of constraints. Nine years of accumulated pattern recognition is what makes this possible. It cannot be shortcut.
// HOW SA CONNECTS TO EVERY DOMAIN IN YOUR T-SHAPE
SA × SECURITY
How does an attacker move through this system? Where are the trust boundaries? SA makes you model the attack surface before it exists — not reactively after a breach.
SA × AI ENGINEERING
AI is not just a model. Training pipelines + serving infrastructure + monitoring + feedback loops. SA holds all those pieces together reliably in production at scale.
SA × CLOUD
Every AWS service selection is an architectural decision. SA turns cloud from a toolbox into a design discipline. Prevents expensive mistakes made early requiring full rewrites later.
SA × WEB DEV
How does data flow from browser to server to database and back? Why REST vs GraphQL? How do you structure a frontend a backend can serve efficiently? SA answers these.
SA × STARTUP
The founding architecture determines whether you scale or rebuild. Most startups fail at scale because of day-one architectural decisions made without SA depth.
SA × AI RESISTANCE
Narrow execution gets automated. Architectural judgment — reasoning about systems that do not yet exist — is irreplaceable human judgment. Your long-term protection.

Technical Writing
Writing is how you build credibility, demonstrate depth, and earn before you have a job. Every article is a permanent asset. Do it properly.
// THE ARTICLE LIFECYCLE — FROM IDEA TO PUBLISHED (3–4 WEEKS PER ARTICLE)
  1. Week 1 — Research and Comprehension. Read widely. Follow threads. Ask questions. By end of week you must be able to explain the core concept verbally without notes. If you cannot, the research is not done. Do not move to writing yet.
  2. Week 2 — Skeleton and First Draft. Write the skeleton first — a sequence of questions the article answers in order. Then write the first draft all the way through without stopping to edit. Finish it ugly. Do not polish while writing.
  3. Week 3 — Deep Editing and Verification. Fact-check every specific claim. Verify every number independently. Read the whole article aloud — where you stumble is where the explanation breaks. Apply the ownership test: close the article and explain the core argument verbally. Where you cannot is where it needs more work.
  4. Week 4 — Polish and Publish. Format for Hashnode. Write meta description (1–2 sentences for search). Prepare LinkedIn summary and TikTok hook. Publish Monday or Tuesday morning. Respond to every comment within 48 hours.
// THE QUALITY TEST — APPLY BEFORE EVERY PUBLISH
  • Can you explain the core argument verbally without looking at the article?
  • Can you define every technical term you used without a dictionary?
  • Is every specific number, CVE reference, and technical claim independently verified?
  • Does every paragraph connect back to the thesis — or is it filler?
  • Would a technically sophisticated reader learn something they did not already know?
  • Does the opening make your target reader feel this was written specifically for them?

// Structure Over Motivation
Discipline Guide
Motivation is temporary and unreliable. Discipline is structural. This section is not here to make you feel good. It is here to keep you grounded when nothing else does.
// ON FILTERING NOISE — READ THIS WHEN YOU OPEN X OR TIKTOK
Every week there is a story about someone making life-changing money from an AI tool, a crypto play, or a viral video. The story is always incomplete. What X does not show you is the existing skills that made it possible, the failed attempts before the one that worked, or the ten people who tried the same thing and made nothing.

The filter to apply before reacting: does this person have skills I do not yet have that made this possible? If yes — the lesson is not “chase this opportunity.” The lesson is “build those skills.” That reframe turns FOMO into directional motivation.

You are allowed 15 minutes of intentional news reading per day. Hacker News. ArXiv titles. One security blog. Then close it. Passive scrolling is not staying current — it is training your brain to want shortcuts.
DAILY STRUCTURE
  • Morning block (2 hrs): Deep technical work. The hardest thing first. No phone, no social media. This is when your brain is sharpest. Protect it fiercely.
  • Afternoon block (1.5 hrs): Lighter work — reading, research, article writing, course videos. Active engagement with notes. Not passive consumption.
  • Evening block (1 hr): Review the day. What do you understand now that you did not this morning? Write it down. Plan tomorrow specifically — not vaguely.
  • Sunday review (30 min): Update the progress tracker. What was the gap between planned and actual work? Close that gap next week specifically.
THE ACCOUNTABILITY RULES
  • Every week without a GitHub commit is a week wasted. Commit something — even notes, even a README update. The streak is the public record.
  • Every month without a published article is a month of credibility not built. Publish on schedule regardless of how the article feels.
  • If you miss a day, do not try to catch up. Resume normally the next day. Catch-up pressure creates unsustainable cycles.
  • Comparing your progress to others at different stages is irrational. Compare only to yourself one month ago. The gap should be closing.
WHEN YOU FEEL LIKE QUITTING
  • You are not behind. The 10-year horizon accommodates real life — power cuts, broken laptops, health, family. These are not setbacks. They are the normal texture of a decade.
  • The feeling that you are not making progress is almost always false. Read your notes from 4 weeks ago. You understand things now that confused you then. That is progress.
  • Do the smallest possible thing instead of nothing. 20 minutes of Bandit. One paragraph of research. One git commit. Starting always beats not starting.
  • The people who succeed in this field are not the most talented. They are the ones who kept going when it was inconvenient and unglamorous — which is most of the time.

  • The roadmap does not get you rich quickly. It gets you to a position where significant wealth becomes structurally possible. These are completely different things.
  • The first article earns nothing. The first ten build an audience. The first twenty build credibility. The first fifty build a reputation. Reputation earns money. Start the count now.
  • You are 20. Every person you admire who built something significant started earlier than the public story suggests and worked longer than the headline implies.

Linux Dual Boot Guide
Everything learned from the installation process documented here so you never repeat the same mistakes. Read this fully before touching a partition.
// READ THIS FIRST — BEFORE ANYTHING ELSE
The dual boot process is not difficult when done in the right order. Every problem encountered during this roadmap's Linux installation came from doing steps out of order, not understanding what each partition does, or interrupting processes midway. This guide fixes all of that.
// PRE-INSTALLATION CHECKLIST — ALL MUST BE TRUE BEFORE STARTING
  • Back up all important data first. Copy documents, Git repos, downloads to an external drive or cloud storage. Non-negotiable. If anything goes wrong your data is safe.
  • Confirm BIOS is set to UEFI mode. Press F2 on startup, go to Boot settings, confirm Boot List Option shows UEFI not Legacy.
  • Confirm Secure Boot is OFF. In BIOS under Secure Boot settings. Must be disabled for Linux to boot.
  • Have at least 40GB free space on your Windows drive. Check in File Explorer → right click C drive → Properties. 50-60GB is better.
  • Have an 8GB+ USB drive available. Everything on it will be wiped. Back up anything on it first.
  • Have a stable power source. Never do partition work or OS installation on battery alone. Plug in throughout.
  • Download Linux Mint ISO from linuxmint.com — choose Cinnamon edition, 64-bit.
  • Download Rufus from rufus.ie — about 1MB, no installation needed.
// STEP 1 — SHRINK WINDOWS PARTITION
Before shrinking, free up as much space as possible so Windows allows a larger shrink amount. Open Command Prompt as Administrator and run:
  • Disable hibernation to free several GB: powercfg /h off
  • Run Disk Cleanup as Administrator — search Disk Cleanup, click Clean up system files, check everything including Windows Update Cleanup
  • Disable System Restore temporarily — search Create a restore point → Configure → Disable system protection on C drive
  • Then open Disk Management: right click Start → Disk Management
  • Right click your C drive → Shrink Volume → enter 51200 for 50GB or 61440 for 60GB
  • If Windows only allows a small shrink amount it means unmovable files are blocking it. Run defragmentation and try again.
  • The shrunk space appears as Unallocated — leave it unallocated. Do not create a new partition. The Linux installer does that.
// STEP 2 — CREATE BOOTABLE USB CORRECTLY
This step is critical. Do not copy the ISO file to the USB drive directly — that never works. Use Rufus with these exact settings:
  • Open Rufus, plug in USB drive, select it in the Device dropdown
  • Click SELECT and choose your Linux Mint ISO file
  • Partition scheme: GPT — your drive is GPT after UEFI setup
  • Target system: UEFI (non CSM) — matches your BIOS mode
  • File system: FAT32 — Rufus sets this automatically
  • Click START, confirm the warning, let it complete fully
  • When Rufus says READY the USB is correctly bootable
⚠ If you get a Rufus warning about Secure Boot — click OK and continue. Since Secure Boot is already off this warning is irrelevant.
// STEP 3 — BOOT FROM USB
  • Plug USB into laptop and restart
  • Immediately press F12 repeatedly as soon as the Dell logo appears — this opens the one-time boot menu
  • Select the USB entry that shows UEFI: prefix before the USB drive name. Not the entry without UEFI prefix.
  • If lines appear on screen after selecting — wait. Do not restart. The display initialises after 30-60 seconds and the Linux Mint menu appears.
  • Select Start Linux Mint from the menu
  • Linux Mint will boot into a live session — a full working desktop running from the USB
// STEP 4 — INSTALLATION
  • Double click Install Linux Mint on the desktop
  • Select language and keyboard layout, click Continue
  • On Installation type screen select Something else for manual partitioning — gives you full control
  • You will see your partitions listed. Find the Unallocated space you created in Step 1.
  • Click the unallocated space, click the + button to create a new partition
  • Create root partition: use all the unallocated space, type Ext4, mount point / (forward slash)
  • For swap: if you have 4GB RAM create a 4GB swap partition before the root partition. Type: swap area.
  • Boot loader location: select your main drive — usually /dev/sda. Not a specific partition. The drive itself.
  • Click Install Now and confirm. Let it run completely — 15 to 30 minutes. Do not interrupt it.
  • When asked to restart — remove USB when prompted and press Enter
⚠ CRITICAL: Never interrupt the installation once it starts copying files. If power cuts or you force restart during installation the partition will be corrupted and require a full reinstall. Stay plugged in throughout.
// STEP 5 — AFTER INSTALLATION
  • On restart you will see GRUB bootloader — a menu asking which OS to boot. This is normal and correct.
  • Select Linux Mint to boot into Linux. Select Windows Boot Manager to boot into Windows.
  • If Windows does not appear in GRUB menu: boot into Linux Mint, open Terminal and type sudo update-grub. This scans for all operating systems and updates the menu.
  • In Linux Mint open Terminal and run: sudo apt update && sudo apt upgrade to update all packages.
  • Install essential tools: sudo apt install git python3 python3-pip nano curl wget
  • Re-enable hibernation in Windows if you disabled it: open Windows Command Prompt as admin and type powercfg /h on
  • Re-enable System Restore in Windows if you disabled it
// CRITICAL LESSONS — WHAT NOT TO DO
  • Never delete all EFI partitions. The EFI partition (usually 100MB FAT32) is what allows UEFI to boot any operating system. Deleting it locks you out of booting from any source including USB drives.
  • Never interrupt an installation once file copying begins. A partial installation is worse than no installation. The partition ends up in a broken half-state that requires complete reinstallation to fix.
  • Never convert MBR to GPT without understanding the implications. Once converted Legacy boot mode is locked out in BIOS on Dell machines. All subsequent USB drives must be created in GPT/UEFI mode.
  • Never modify partition table entries without knowing exactly what each partition does. Before deleting any partition: identify its type, size, and role. System partitions, EFI partitions, and recovery partitions all serve specific functions.
  • Always have a backup before touching partitions. Partition operations are irreversible. Data loss from partition mistakes is permanent.
  • If something unexpected happens during installation — stop and research before proceeding. An interrupted decision is recoverable. A wrong completed action often is not.
// UNDERSTANDING YOUR PARTITION TABLE
A standard Windows 10/11 GPT installation creates these partitions automatically. Know what each one is before touching anything:
EFI SYSTEM PARTITION
100MB FAT32. Contains bootloader files. UEFI firmware looks here first on every boot. Never delete this.
MSR PARTITION
16MB Reserved. Required by Windows on GPT disks. No filesystem visible. Do not touch.
WINDOWS PARTITION
Large NTFS partition. Your C drive. Windows system files and personal data live here.
RECOVERY PARTITION
500MB+ NTFS. Windows Recovery Environment. Used for repair and reset options. Safe to keep.
LINUX ROOT /
ext4 partition you create. Minimum 40GB. The entire Linux operating system and your files live here.
SWAP PARTITION
Optional. Equal to RAM size (4GB for your machine). Used as overflow when RAM is full. Helps with 4GB RAM systems.
// TROUBLESHOOTING COMMON PROBLEMS
  • USB not booting: Confirm BIOS Boot List is UEFI. Press F12 for one-time boot menu. Select the UEFI: USB entry not the plain USB entry. Check Secure Boot is off.
  • Rufus BIOS/Legacy boot error on screen: You booted the USB in Legacy mode. Go to BIOS, confirm UEFI mode, press F12 and select the correct UEFI USB entry.
  • Windows disappears from GRUB after Linux install: Boot Linux, open Terminal, type sudo update-grub. Windows will reappear in the boot menu.
  • Cannot shrink Windows partition enough: Run powercfg /h off, Disk Cleanup with system files, disable System Restore temporarily. Then try shrinking again.
  • Installation fails with partition error: Do not force retry immediately. Boot into live Linux session, open GParted (comes with Linux Mint), check the partition layout carefully before proceeding.
  • Black screen after selecting Linux in GRUB: Wait up to 60 seconds. If still black, restart and at GRUB menu press E to edit, find the line with quiet splash and change to nomodeset, press F10 to boot. This is a graphics driver issue that resolves after installing proper drivers.
